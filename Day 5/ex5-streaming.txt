On to #5, the last topic: streaming.

Everything so far assumed the response arrives all at once — you await response.json() and get the full text in one shot. Streaming is different: instead of waiting for the complete response, the server sends the response in small chunks as the model generates them, and your code processes each chunk as it arrives. This is what makes ChatGPT/Claude's UI show text appearing word-by-word instead of all at once after a pause.

Why this isn't just a UX detail — it changes your code's shape:

Non-streaming: one await, one parse, one return value. Simple, linear.
Streaming: you get a stream of events over time, each one a small piece (a token or few), and you are responsible for accumulating them into the full text as they arrive — there's no single "final response object" handed to you at the end unless you build it yourself by concatenating chunks.

This matters for your take-home/interview specifically: if you're building something that displays output progressively, or that needs to react to partial output (e.g., detecting an early signal in a long generation), you need streaming. If you just need the final answer to feed into more code, non-streaming is simpler and you shouldn't reach for streaming just because it's "how the real apps do it."

Real streaming with Anthropic's SDK looks conceptually like this (simplified, not exact SDK syntax):

typescript
const stream = await anthropic.messages.stream({ model, max_tokens, messages });

let fullText = "";
for await (const event of stream) {
  if (event.type === "content_block_delta") {
    fullText += event.delta.text;
    console.log(event.delta.text); // process each chunk as it arrives
  }
}
// fullText now has the complete response, built up piece by piece
