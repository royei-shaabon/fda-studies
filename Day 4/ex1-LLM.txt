1. What Claude Code / Cursor actually do

Both tools put an LLM in a loop with your file system: it can read files, write/edit files, run commands, see the output (errors, test results), and iterate — without you manually copy-pasting between a chat window and your editor.

The critical thing to internalize: the model is not reasoning about your codebase the way you do. It's pattern-matching against enormous amounts of code it's seen, plus whatever context (files, errors) it's been given in this session. That means:

It will confidently write code that's syntactically perfect and logically wrong — same failure mode you already hit twice this week by hand (type-safe ≠ logically correct). The tool doesn't fix that problem, it just moves it up a level.
It has no persistent memory of your intent unless it's in the prompt or the file. If you don't say it, it doesn't know it.
It will happily generate a plausible-looking solution to a vague spec rather than asking you what you meant — vagueness gets silently resolved in whatever direction the training data leans, not necessarily your direction.

So the skill isn't "prompt the tool." It's: specify precisely, read everything it produces, and verify it against your own understanding before you trust it — the exact discipline you've been building all week, just aimed at someone else's (the AI's) code instead of your own.
