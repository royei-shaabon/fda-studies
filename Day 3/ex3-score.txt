Writing a scoring function with explicit, explainable criteria

This is the heart of your take-home requirement — "deterministic scoring or ranking logic," and it needs to be explainable, not a black box. Let's build the pattern properly.

The core idea: a scoring function takes a structured record and returns a number (or a number + explanation) representing how well it performs against criteria you define. The key discipline: each criterion should be a clear, named, isolated piece of logic — not one tangled formula — so you can explain why something scored the way it did.

Example — scoring airports for "terminal expansion investment potential" using two criteria: high passenger volume is good, high delay rate is bad (congestion signals need for expansion, but also risk):

typescript
interface Airport {
  code: string;
  name: string;
  passengers: number;
  delayRatePercent: number;
}

function scorePassengerVolume(airport: Airport): number {
  // simple normalization: 1 point per million passengers
  return airport.passengers / 1_000_000;
}

function scoreDelayPenalty(airport: Airport): number {
  // higher delay rate = bigger penalty
  return -airport.delayRatePercent * 0.5;
}

function scoreAirport(airport: Airport): number {
  return scorePassengerVolume(airport) + scoreDelayPenalty(airport);
}

Notice the structure: each criterion is its own named function, and the final score composes them. This matters for two reasons: (1) it's easy to explain each piece separately ("this airport scored high because of passenger volume, despite a delay penalty"), and (2) it's easy to test/adjust one criterion without touching the others — exactly what you'd want when an interviewer asks "what if we weighted delay more heavily?"
