1. Modules: import / export

Every exercise so far has lived in one file. Real projects don't. TypeScript (like modern JavaScript) uses ES modules: each file is its own scope, and you explicitly export what other files are allowed to use, and import what you need from elsewhere.

typescript
// types.ts
export interface Message {
  role: "user" | "assistant";
  content: string;
}

export interface RequestBody {
  model: string;
  max_tokens: number;
  system?: string;
  messages: Message[];
}
typescript
// api.ts
import { Message, RequestBody } from "./types";

function buildRequest(history: Message[]): RequestBody {
  // ...
}

Two forms worth knowing the difference between:

Named exports (export interface Message, export function foo) — you import { Message } from "./types", and you can have as many named exports per file as you want.
Default export (export default function foo() {}) — one per file, imported without braces: import foo from "./file".

Named exports are far more common in real TypeScript codebases (including what you'll likely see in a take-home) because they're explicit and don't rely on the importer guessing what a nameless default was called.
